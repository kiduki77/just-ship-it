# 운영 개선 할 일 목록

2026-11-02 조사 결과를 할 일로 정리한 목록입니다. 목표는 오너가 하루 몇 번 들러 결정만 하면 회사가 며칠씩 혼자 일하는 상태입니다.

근거 표시는 세 가지입니다.

- **재현함.** 테스트 DB에서 직접 실행해 확인했습니다.
- **코드 확인.** 해당 줄을 읽어 확인했습니다. 실행은 하지 않았습니다.
- **추론.** 코드나 기록에서 짐작한 것입니다. 확인이 더 필요합니다.

크기는 추측입니다. S는 반나절, M은 하루에서 사흘, L은 그 이상입니다.
P-5 수치는 [research/p5-history.md](ux/research/p5-history.md)(2026-11-01 조회)에서 가져왔습니다.

## 먼저 할 순서

1. A1, A3, C1, C2. 작업 중복 실행, 조용한 실패, 호스트 코드 실행, 무인증 API를 막습니다.
2. B1, C3, A2, B3. 오너 알림, 백업, 할당량 대기, 첫 실행을 정리합니다.
3. D1, D2, D3, D6, D7. 인터뷰, 결정 나누기, 도전 실행 연결, 오너 할 일, 점검일을 만듭니다.

## A. 무인 실행이 멈추거나 두 번 돌지 않게 합니다

- [ ] **A1. 작업 리스를 갱신하고 회수 규칙을 고칩니다.** 크기 M.
  - 근거 (재현함). `services/queue.py:31-33`은 2시간 넘게 running인 작업을 회수합니다. 실행 중에 `locked_at`을 갱신하는 곳은 없습니다. worker-A가 잡은 작업을 2시간 1분 뒤 worker-B가 다시 잡았고, `attempts`는 2, `max_attempts`는 1이었습니다.
  - 근거 (코드 확인). `dev_job`은 payload에 `project_id`가 없어 락을 잡지 않습니다(`workers/runner.py:53-58`, `engineering/specs.py:121`). 락은 프로세스 안에서만 유효합니다.
  - 완료 조건. 살아 있는 작업은 몇 시간이 지나도 다른 워커가 잡지 않습니다. heartbeat가 끊긴 작업만 회수됩니다. 회수도 `max_attempts`를 지킵니다. 개발 작업과 프로젝트 실행은 DB 잠금으로 한 번에 하나만 돕니다. 위 세 경우마다 테스트가 있습니다.
- [ ] **A2. 구독 할당량이 소진되면 실패 대신 대기합니다.** 크기 M.
  - 근거 (코드 확인). 두 provider가 모두 소진되면 `_routes`가 즉시 `AgentFailed`를 던집니다(`agents/executor.py:62-65`). FAILED는 끝난 상태로 취급되어 뒤 업무가 연쇄로 실패합니다(`services/tasks.py:134-136`). `run_project`는 `max_attempts=1`입니다(`services/projects.py:34`).
  - 완료 조건. 할당량이 없으면 업무가 "할당량 대기"로 멈춥니다. 초기화 시각이 지나면 자동으로 재개됩니다. 대기 중인 업무에 의존하는 업무는 시작하지 않습니다.
- [ ] **A3. 실패한 작업, 꺼진 워커, 멈춘 실행을 경고로 보여 줍니다.** 크기 S.
  - 근거 (코드 확인). `_alerts`(`api/console.py:131-171`)는 프로젝트, 예산, 업무, 개발 작업만 봅니다. 명세 작성, 머지, 외부 실행, 재정렬, 수용 검수의 실패는 감사 화면에만 남습니다. `jobs` 테이블은 실시간 감시 대상이 아닙니다(`services/events.py`의 `_WATCHED`). 워커 heartbeat도 없습니다.
  - 완료 조건. 실패한 큐 작업, N분 동안 응답 없는 워커, RUNNING인데 처리 중인 작업이 없는 프로젝트가 홈 경고에 나옵니다.
- [ ] **A4. 만료된 요청을 처리합니다.** 크기 S. 오너 결정 필요(아래 결정 3).
  - 근거 (코드 확인). 요청은 144시간 뒤 만료되고(`services/requests.py:100`), 만료 뒤에는 승인과 답변이 거부됩니다(`requests.py:136-139`). 만료 상태로 바꾸는 작업도, 연장하는 경로도 없습니다. 콘솔은 만료된 요청에도 승인 버튼을 켭니다.
  - 완료 조건. 만료가 가까운 요청이 경고에 나옵니다. 만료된 blocking 요청은 결정 3에서 정한 방식으로 처리됩니다.
- [ ] **A5. 콘솔의 재시도가 체크포인트 유실에서도 동작하게 합니다.** 크기 S.

  - 완료 조건. 체크포인트를 지운 프로젝트를 콘솔에서 재시도하면 업무 DB로 재구성해 이어 갑니다.

    - 종료 신호를 받아도 작업을 마무리하지 않습니다. 메인 루프의 `claim`은 DB 오류를 잡지 않습니다(`workers/runner.py:103-106`).
  - 완료 조건. 워커를 강제 종료하고 다시 켜면 남은 예약, 남은 컨테이너, 잠긴 작업이 정리됩니다. Postgres가 잠깐 끊겨도 워커가 죽지 않습니다.
- [x] **A7. Redis가 잠깐 끊겨도 프로젝트가 실패하지 않게 합니다.** 크기 S. 2026-11-08 Redis를 없애면서 해당 없음이 됐습니다.

## C. 보안과 데이터를 지킵니다

- [ ] **C1. 엔지니어가 호스트에서 코드를 실행하는 길을 막습니다.** 크기 S~M.
  - 근거 (코드 확인. 공격은 실행하지 않았습니다).
    - 컨테이너는 `.git`을 포함한 clone을 쓰기 가능하게 마운트합니다(`runtime/claude_cli.py:127`).
    - 호스트 워커는 hooks를 끄지 않고 그 clone에서 `git add`와 `git commit`을 실행합니다(`engineering/worker.py:296-298`). 엔지니어가 `.git/hooks/pre-commit`을 쓰면 그 hook이 오너 권한으로 호스트에서 실행됩니다.
    - 테스트 명령은 이미지가 없거나 Docker가 꺼져 있으면 호스트 셸에서 실행됩니다(`worker.py:124-132`).
  - 완료 조건.
    - 호스트 git 호출에는 모두 `-c core.hooksPath=/dev/null -c core.fsmonitor=false`가 붙습니다.
    - 테스트의 호스트 폴백은 사라지고, 테스트 컨테이너에는 `--cap-drop ALL`, `--network none`, `--pids-limit`, `--user`가 붙습니다.
    - hook을 심은 clone으로 커밋해도 hook이 실행되지 않는 회귀 테스트가 있습니다.
- [ ] **C2. API에 인증과 Host/Origin 검사를 넣습니다.** 크기 M.

  - 완료 조건.
    - 모든 변경 요청에 로컬 토큰이 필요합니다. 토큰은 `ship init`이 만들고, 콘솔은 처음 열 때 받습니다.
    - 허용되지 않은 Host·Origin은 거부됩니다. 0.0.0.0에 바인딩하면 경고가 나옵니다.
    - 위조 요청 테스트가 있습니다.
