# 오너 콘솔 설계 요약 (shape)

2026-11-03, `/impeccable shape`. 근거: [08-first-100.md](08-first-100.md)(3~12절), [09-expert-panel.md](09-expert-panel.md) 5·6절,
[04-design-system.md](04-design-system.md)(토큰), 스타일은 08 10절(흰 바탕, 그림자 없음, 검정·회색 두 단계 글자, 굵은 핵심어 + 회색
보조, 색은 배지와 상태에만, 테두리 보조 버튼). 화면 모드는 Operate입니다.

오너 결정(같은 날):
- 홈은 "오늘 할 일" 하나로 묶습니다. 결정, 게시, 연락을 구분하지 않고, 오늘 오너만 할 수 있는 일을 급한 순서로 최대 3개 보여 줍니다.
- 왼쪽 메뉴는 5개(홈, 결정, 내 할 일, 사업, 설정)와 접힌 "회사 내부 보기"입니다.
- 사업은 한 번에 하나를 봅니다. 위쪽에서 사업을 고릅니다.

## 1. 누가, 어떤 상태로 오나

하루 두세 번 PC로 들르는 1인 창업자입니다. 회사를 지켜보러 오지 않습니다. "지금 나만 할 수 있는 일"을 끝내고 나가려고 옵니다.
실사용자 검토에서 가장 큰 이탈 지점은 "승인 뒤의 침묵"과 "메뉴 12개"였습니다(09 5절).

## 2. 해야 할 일과 성공

- 홈에서 오늘 할 일을 처리합니다. 각 일은 그 자리에서 끝나거나, 한 번 눌러 해당 화면으로 갑니다.
- 성공은 하루 사용 20분 안에 할 일이 0이 되는 것입니다. 오너가 쓴 시간을 사용자와 보낸 시간과 검토 시간으로 나눠 잽니다(09 6절 11번).

## 3. 정보 구조

| 메뉴 | 화면 | 담는 것 |
|---|---|---|
| 홈 | 오늘 | 오늘 할 일(최대 3개, 전체 수), 어제 회사가 한 일 3줄, 숫자 하나(두 번 이상 쓴 사람 / 목표 N), 진행 중인 시작 대화 |
| 결정 | 결정 카드 목록과 상세 | 결정 카드(숫자, 대안별 근거·위험, CEO 권고, 승인하면 바로 일어날 일, 되돌릴 수 있나), CEO가 대신 정한 일 기록(접힘) |
| 내 할 일 | 오너 할 일 목록과 상세 | 게시 카드(개요/초안 모드), 연락·같이 설치·후속 연락·소개 부탁, 참여, 공개·계정·지출. 완료 입력(링크, 단계, 그 사람이 한 말, 다음 날짜) |
| 사업 | 사업 한 곳의 모든 것 | 지시서(출처 배지 + 인용문), 도전(실행 중·회고 대기·후보), 사람 명단(단계별), 아이디어함, 숫자(관심·첫 가치·반복), 완료 기준 |
| 설정 | 설정 | 사용량(구독 % 표시), 연결(필요할 때 하나씩, 단계별 안내, 연결 시험), 커넥터 모드, 알림, 결정 권한 규칙 |
| 회사 내부 보기(접힘) | 기존 화면 | 업무, 에이전트, 조직도, 개발팀, 스킬, 비용, 활동 기록, 정기 업무 |

사업 고르기는 화면 맨 위 머리줄에 있습니다. 사업이 하나뿐이면 이름만 보입니다. "새 사업 시작"은 사업 고르기 안에 있습니다.

## 4. 홈의 "오늘 할 일"

- 서버가 한 목록으로 만들어 줍니다. 종류: 막힌 결정, 결정 카드, 오너 할 일(게시, 연락, 후속 연락, 참여 등), 버림 제안 아이디어, 오너 차례인 시작 대화,
  "오너가 정리" 표시가 붙은 옛 도전, Slack 연결 끊김 같은 경고.
- 급한 순서: 회사를 막고 있는 것 → 날짜가 지난 후속 연락 → 오늘 날짜 → 나머지. 같은 급함이면 예상 시간이 짧은 것 먼저.
- 줄마다: 종류 배지, 한 줄 제목, 회색 보조 정보(사업 아님, 사업은 위에서 고름: 예상 시간 · 마감 · 이유), 오른쪽 테두리 버튼 하나(결정, 열기, 완료).
- 3개를 넘으면 "나머지 N개 보기"로 내 할 일과 결정 화면에 이어 줍니다.
- 할 일이 0이면 "오늘은 오너님이 할 일이 없어요. 회사가 다음 일을 하고 있어요."와 어제 한 일을 보여 줍니다.

**어제 회사가 한 일.** 활동 기록을 서버가 세어 만든 세 줄입니다(모델 호출 없음). 예: "사람 4명을 찾았어요 · 도전 1개 회고를 끝냈어요 · 게시 카드 2개를 준비했어요".

**숫자 하나.** 완료 기준 문장과 같은 숫자인 두 번 이상 쓴 사람 수와 목표(지시서의 N)를 보여 줍니다. 옆에 회색으로 첫 가치에 닿은 사람 수와 관심(star) 숫자를 작게 둡니다.

## 5. 상태와 범위

| 상태 | 보이는 것 |
|---|---|
| 사업이 없음 | "새 사업 시작" 하나와 한 줄 설명 |
| 시작 대화 중 | 오늘 할 일 맨 위에 "시작 대화 이어 하기" |
| 지시서 승인 전 | "지시서 확인하고 시작하기" |
| 할 일 0 | 위 4절 문구 |
| 사용량 대기 | 머리줄에 "사용량 상한으로 내일 00:00까지 대기" 한 줄 |
| Slack 연결 끊김 | 오늘 할 일에 "Slack 다시 연결" |
| 로드 실패 | 조용한 오류 한 줄과 다시 시도 |

분량: 오늘 할 일은 0~3개(+나머지 수). 사업은 1~5개. 제목은 한국어 1~2줄, 영어가 들어와도 길이를 가정하지 않습니다.

## 6. 상호작용

- 결정은 결정 카드를 옆 패널로 열어 그 자리에서 승인, 반려, 보류합니다. 강한 승인은 지금처럼 확인 입력을 받습니다.
- 오너 할 일은 열면 카드 전체(어디에, 무엇을, 언제, 왜, 점검 줄)가 나오고, 링크 복사와 "열기"(새 탭) 버튼, 완료 입력이 있습니다.
  개요 모드 카드에는 문장이 없다는 안내("이 채널은 직접 쓰셔야 해요")가 있습니다.
- 숫자를 누르면 사업 화면의 숫자 칸으로 갑니다.
- 실시간: 기존 SSE로 목록이 갱신됩니다. 방금 처리한 줄은 조용히 사라집니다.
- 키보드: 오늘 할 일은 j/k로 이동, Enter로 열기. 휴대폰은 전용 화면을 만들지 않지만 좁은 화면에서 깨지지 않습니다.

## 7. 제약과 열린 결정

- WCAG 2.2 AA, 색만으로 상태를 구분하지 않습니다. 화면 말은 쉬운 말로 씁니다(door_policy, deny, 플레이북 같은 말을 화면에 쓰지 않음).
- B-1, P-1 같은 코드는 숨기고, 필요한 곳에서만 회색 작은 글씨로 보입니다.
- 이 요약은 홈, 메뉴, 사업 고르기를 먼저 만들고(F8a), 결정·내 할 일(F8b), 사업(F8c), 설정·시작 대화 보완(F8d)을 그 위에 만듭니다.
  각 화면은 이 요약을 따르고, 화면마다 새로 정할 것이 생기면 그 PR에서 shape 질문을 다시 합니다.
