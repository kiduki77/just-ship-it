화면마다 **목적 하나**와 **내용 우선순위**를 고정합니다. 우선순위는 위에서 아래로, 왼쪽에서 오른쪽으로 읽히는 순서입니다.
와이어프레임: https://claude.ai/artifact/JxrpqqdcKFsjTaPUajhJp9 (비공개 캔버스).
원본은 [wireframes/](wireframes/)에 있고 화면은 SC-01, SC-02(데스크톱·390px), SC-04, SC-05입니다. 내용은 모두 P-5 실데이터입니다.

## 2. 화면별 설계

### SC-01 홈

우선순위는 다음과 같습니다.
1. **나를 기다리는 결정.**
   - 차단 요청이 먼저 오고, 그다음은 만료가 가까운 순입니다. 최대 5건을 보여 주고 나머지는 "외 n건"으로 줄입니다.
   - 항목마다 한 줄 요청, 차단 여부, 프로젝트, 요청자, 경과 시간을 보여 줍니다.
2. **지난 방문 이후.**
   - 완료된 업무, 새 결정(DEC), 새 요청, 실패, 재정렬을 각각 숫자와 상위 3건 링크로 보여 줍니다.
   - "확인함"을 누르면 기준 시각이 지금으로 바뀝니다.
   - 기준 시각이 없는 첫 방문에는 최근 24시간을 보여 줍니다.
3. **프로젝트 상태 줄.** 프로젝트마다 한 줄입니다.
   - 상태 점과 상태 라벨, 단계(수명주기 위치), 멈춘 이유(요청 ID나 오류 요약), 업무 진행, 예산을 보여 줍니다.
   - 복구가 가능하면 복구 버튼을 같은 줄에 둡니다.
4. **사용량 한 줄.** 이번 달 환산액과 한도를 보여 주고 사용량 화면으로 연결합니다.

빼는 것과 옮기는 것은 다음과 같습니다.
- 숫자 타일 4개는 뺍니다. 상태 줄과 지난 방문 이후가 같은 정보를 더 정확하게 줍니다.
- "지금 일하는 에이전트" 카드는 상태 줄의 "진행 중 업무"에 합칩니다.
- 새 목표 폼은 프로젝트 목록과 "새 목표" 버튼으로 옮깁니다. 지금은 첫 화면의 1/4을 차지합니다.

### SC-02 결정함

이 콘솔의 핵심 화면입니다. 왼쪽은 목록, 오른쪽은 상세입니다.

**목록.**
- "대기" 그룹을 맨 위에 두고, 차단 요청을 먼저 보여 줍니다.
- 그 아래는 "방금 처리함"(이번 방문에서 결정한 것)입니다.
- "처리됨"은 오너가 실제로 결정한 것만 보여 줍니다(APPROVED, ANSWERED, DEFERRED, REJECTED). 시스템이 처리한 것(CANCELLED, AUTO_APPROVED, EXPIRED, DENIED_BY_POLICY)은 "시스템 처리"로 접어 둡니다.
- 프로젝트 필터와 종류 필터는 URL에 남깁니다.

**상세.** 위에서 아래로 다음 순서입니다.
1. **헤더.** REQ 번호, 한 줄 제목, 차단 여부, 종류, 위험도, 정책 모드, 요청자, 프로젝트·업무 링크, 만료.
2. **무엇을 결정하나.** 요청 내용의 첫 문단(최대 3줄)을 보여 줍니다. 이 문단은 에이전트가 쓰는 "한 줄 요청"을 계약으로 정해 받습니다(05 참조).
3. **선택지별 결과.** 선택지마다 이 결정이 무엇을 일으키는지 보여 줍니다.
   - 동작 종류(action_kind)와 차단 여부로 정해지는 결과는 서버가 계산해 줍니다. 예: 재개, 머지, 개발 착수, 공개 동작 대기열.
   - 지금 결정 뒤 영수증에 나오는 문구를 **결정 전에** 보여 주는 셈입니다.
4. **근거 확신도.** 본문이 인용한 EV를 종류와 검증 상태별로 세어 막대 한 줄로 보여 줍니다. 칩을 펼치면 근거를 그 자리에서 볼 수 있습니다.
5. **결정 바.** 데스크톱에서는 오른쪽에 고정되거나 상세 아래에 붙어서 항상 화면 안에 있습니다. 담는 것은 다음과 같습니다.
   - 선택지 라디오와 직접 답변
   - 메모
   - 강한 승인일 때 번호 입력
   - 주 버튼과 보조 버튼

   지금의 결정 규칙은 그대로 둡니다. 문구로 승인 여부를 추측하지 않고, 애매한 문구는 결정을 직접 고르게 합니다.
6. **요청 내용과 근거 전문.** 접어 두고, 길이를 함께 표시합니다(예: "전문 3,926자 펼치기").

**결정 흐름의 상태 전이(화면 기준)**

```
보는 중 ─(선택·입력)→ 결정 준비됨 ─(제출)→ 처리 중(버튼 잠김, aria-busy)
   ├─ 성공 → 영수증(결정·선택·메모·응답자·시각 + 시작된 일) → [다음 결정 →] 또는 j
   └─ 실패 → 같은 요청에 오류 고정(다른 요청으로 가도 목록에 표시) → 다시 시도
만료된 요청: 승인·답변 버튼 없음, "만료됨: 반려하거나 보류하세요"
다른 곳에서 처리됨(라이브 갱신): 상세는 그대로 두고 상단에 "다른 곳에서 처리됨 · 결과 보기"
```

키보드 동작은 다음과 같습니다.
- `j`/`k`: 목록 이동
- `Enter`: 결정 바로 초점 이동
- `Ctrl+Enter`: 주 버튼 실행. 주 버튼이 승인이고 강한 승인이면 번호를 입력하기 전까지 동작하지 않습니다.

### SC-03 프로젝트 목록

- 표 형식이고, 행은 다음과 같습니다.
  `P-n · 이름 · 상태 · 단계 · 멈춘 이유 · 업무 · 예산 · 대기 결정 · 갱신`
- 필터: 진행 중(기본), 오너 대기, 종료, 보관, [TEST].
- "새 사업 목표" 버튼을 누르면 오른쪽 패널이 열립니다. 목표, 이름(선택), 예산(선택, 기본값 표시)을 입력합니다.
- 프로젝트가 만들어지면 그 프로젝트 개요로 이동합니다.

### SC-04 프로젝트 개요

1. **헤더.** P 번호와 이름, 그리고 **상태 줄**이 들어갑니다.
   - 수명주기 띠: 계획 → 실행 → CEO 검토 → (회의) → 결정 → 종료. 현재 위치를 표시하고 몇 바퀴째인지 보여 줍니다.
   - 멈춘 이유와 복구 동작.
2. **다음에 일어날 일.** 지금 단계에서 무엇을 기다리는지 한 문장으로 씁니다. 예: "CEO 최종 결정이 REQ-66 승인을 기다립니다", "T-71 시장조사 진행 중(시도 2)".
3. **오너 지시와 반영.**
   - 최근 지시 3건과 각각의 재정렬 결과(취소, 수정, 추가)를 보여 줍니다.
   - [지시 남기기]를 둡니다. 이 기능은 백엔드 추가 후에 넣습니다.
4. **핵심 결정.**
   - 유효한 결정(DEC)마다 판정, 한 줄 근거, 근거 확신도 막대를 보여 줍니다. 전문은 결정 탭에 둡니다.
5. **계획 요약.**
   - 목표 두 줄과 "전체 보기", 성공 기준, 핵심 불확실성을 보여 줍니다.
   - CEO의 목표 해석은 접어 둡니다.
6. **오른쪽 열.** 진행(업무 n/m, 시도, 재작업), 예산, 지금 일하는 에이전트, 최근 활동 5건.
7. **맨 아래.** 프로젝트 관리: 예산 변경, 재실행, 보관(화면 안에서 두 단계로 확인).

CEO 검토 기록 전문은 개요에서 빼고 결정 탭의 "검토 기록"으로 옮깁니다. 이것으로 M1(8,393px)을 해소합니다.

### SC-05 업무

- 칸반 5열(대기, 진행, 검토, 완료, 실패·취소)은 유지합니다. 취소 열은 기본으로 접습니다.
- 카드를 선택하면 상세가 **오른쪽 패널**에 열립니다. 보드 아래로 열리던 방식은 없앱니다.
- 패널 내용: 목표, 완료 기준과 충족 여부, 독립 검토(검토자, 회차, 판정, 미충족, 반론), 요약, 근거 확신도, 상세 결과(접힘), 미해결 질문.
- 900px보다 좁으면 패널이 전체 화면 시트가 됩니다.

### SC-06 결정

- 유효한 결정을 먼저, 대체된 결정은 접어서 아래에 둡니다.
- 결정 카드: 판정, 상태, 근거, 찬성·반대 근거 칩, 확신도 막대, 미해결 질문, 이 결정을 낳은 회의(M) 펼치기.
- "CEO 검토 기록" 섹션에는 라운드별 판정과 전문을 접어 둡니다.

### SC-07 근거

- 지금 구조(종류·검증 필터 칩, 검색, 50행씩 보기)를 유지합니다.
- 필터를 URL에 남깁니다.
- 위쪽에 **종류×검증 매트릭스**를 둡니다(5×13 중 값이 있는 칸만). 칸을 누르면 그 조합으로 거릅니다.
- 행에서 "이 근거를 인용한 곳"(결정, 요청, 업무)을 보여 줍니다. 이 기능은 백엔드 추가 후에 넣습니다.

### SC-08 문서

- 최종 보고서를 목록 맨 위에 고정합니다. 나머지 산출물은 업무별로 묶습니다.
- 본문은 최대 72자 너비로 보여 주고, 목차는 제목에서 자동으로 만듭니다.

### SC-09 개발

- 명세 표와 개발 작업 목록·상세는 유지합니다.
- 상세 맨 위에 **머지 준비 상태**를 둡니다: 수용 기준 충족 n/m, 리뷰 결과, 대상 저장소와 브랜치, 대기 중인 머지 요청 링크.
- 실패한 작업에는 실패 이유와 [재시도]를 둡니다.

### SC-10–13 회사 관리

- 조직: 지금의 조직도와 키보드로 쓰는 목록을 유지하고, 프로젝트 범위를 URL에 남깁니다.
- 스킬: [Skill Factory 실행]에 화면 안 확인 단계를 추가합니다.
- 자동화: 모든 동작에 처리 중, 성공, 실패 표시를 붙입니다. 지금은 실패해도 아무 표시가 없습니다.
- 사용량: 사용액을 프로젝트별로도 나눠 보여 줍니다.

## 3. 공통 상태 규칙

모든 데이터 영역은 아래 상태 중 하나를 **반드시** 보여 줍니다. 빈 화면이나 영원한 "불러오는 중"은 허용하지 않습니다.

| 상태 | 표현 | 문구 예 |
|---|---|---|
| 로딩(첫 진입) | 영역 자리에 같은 크기의 스켈레톤을 둡니다. 300ms 미만이면 표시하지 않습니다 | 없음 |
| 빈 상태 | 왜 비었는지, 언제 채워지는지, 할 수 있는 일을 알려 줍니다 | "아직 결정이 없습니다. CEO가 업무 결과를 검토한 뒤 기록합니다." |
| 오류 | 무엇이 실패했는지와 [다시 시도] | "근거를 불러오지 못했습니다(서버 응답 500). 다시 시도" |
| 연결 끊김 | 사이드바 상태 표시. 화면 데이터는 유지하고 상단에 얇은 띠로 "실시간 갱신이 멈췄습니다 · n분 전 데이터" | |
| 오래된 데이터 | 끊김이 30초를 넘으면 시각을 함께 표시합니다. 다시 연결되면 한 번 전체 갱신합니다 | |
| 처리 중 | 버튼에 "처리 중…"을 표시하고 잠그며, 영역에 `aria-busy`를 둡니다 | |
| 성공 | 결과 영수증(결정)이나 화면 안 확인 문구. 토스트는 쓰지 않습니다 | |
| 보관됨 | 상단 띠와 읽기 전용. 동작 버튼을 숨깁니다 | |
| [TEST] | 전역 토글을 따르고 모든 회사 범위 화면에서 똑같이 적용합니다 | |

**라이브 갱신 규칙.**
- 읽고 있는 항목은 갱신 때문에 바뀌거나 사라지지 않습니다(선택 고정).
- 목록 순서가 바뀌면 "새 항목 n건" 띠로 알립니다.
- 정상적인 진행은 소리나 강조 없이 반영합니다. 강조는 오너가 해야 할 일이 새로 생겼을 때만 씁니다.
