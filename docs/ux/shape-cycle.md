# Shape: 사이클이 보이는 대시보드

2026-11-06, 오너 요청으로 정함. 화면 방향만 정하는 문서이고 코드는 없다. 구현은 `/pstack:poteto-mode`로 한다.

오너의 말: "approve 한 다음부터는 갑자기 얘가 뭘하는데, 뭐하는지를 모르겠어. 흐름을 알아야 사용자도 뭐하고 있구나 하지."
"어느 agent가 어느 사이클의 무슨 작업 중이다. 이런거 있으면 눈에 확 들어오잖아."

## 1. 누가, 언제, 왜

- 하루에 몇 번 들르는 1인 창업자다. Operate 화면이다.
- 계획을 승인한 순간부터 회사가 무엇을 하는지 보이지 않는다. 사이클의 뼈대(사업 → 주기 → 실험 → 회고,
  `08-first-100.md` 4장)는 있지만, 그것을 오너에게 설명하고 동의를 받는 순간이 없다.
- 오너는 사이클이 무엇으로 이뤄졌는지 알고, 단계마다 동의한 만큼만 사용량을 쓰기를 원한다.

## 2. 성공의 모습

- 대시보드를 열면 한눈에 보인다. 몇 번째 사이클의 몇 번째 단계인지, 어느 에이전트가 그 단계의 어느 업무를 하는지,
  다음에 무엇이 오는지, 오너가 할 일이 무엇인지.
- 쓰인 사용량은 모두 오너가 시작한 단계에 속한다. 오너가 시작하지 않은 단계는 돌지 않는다.

## 3. 흐름 (오너 결정 반영)

1. **승인 직후.** "CEO가 첫 사이클을 짜고 있어요"와 경과 시간. 키크오프의 대기 표시(`Waiting`)를 그대로 쓴다.
2. **사이클 제안.** CEO가 두세 문장으로 이번 사이클을 설명하고 단계 목록을 올린다.
   - 단계는 사업마다 CEO가 맞춘다. 기본 틀은 정의 → 기획 → 설계 → 검증 → 개발 → 홍보 → 반응 확인 → 리뷰 반영 → 다시 홍보다.
   - 단계마다 회사가 하는 일, 오너가 할 일, 예상 시간과 사용량, 결정이 필요한 지점을 보인다.
   - 버튼은 "시작"과 "바꿀 점 말하기"다. 오너가 적으면 CEO가 고친 판을 다시 올리고, 바뀐 곳을 표시한다(원칙 4).
3. **실행.** 시작한 단계 하나만 돈다. 그 단계는 세부 업무로 펼쳐 보인다.
4. **단계 끝마다 멈춤** (오너 결정). 무엇을 했는지, 쓴 비용, 나온 근거(확신도 표시)를 요약한다. 버튼은
   "다음 단계: ○○ 시작", "바꿀 점 말하기", "여기서 멈추기"다. 이 카드는 결정이라서 대시보드 맨 위에 온다(원칙 1).
5. **사이클 끝.** 회고(기존 실험 회고 모양)를 하고 다음 사이클 제안으로 이어진다.
6. **이미 돌고 있는 사업** (오너 결정). 진행 중인 일은 멈추지 않는다. CEO가 지금 일을 단계에 배치해 사이클 제안으로 보이고,
   다음 단계부터 단계마다 멈춘다.

## 4. 대시보드 구성 (위에서 아래로)

1. PageHead와 상태 한 문장. 예: "2번째 사이클 · 검증 단계 · 에이전트 3명 작업 중", "검증 단계가 끝났어요. 다음 단계를 정해 주세요."
2. 오너를 기다리는 것. 단계 관문 카드, 막힌 결정, 사이클 제안이 여기 온다.
3. **사이클 줄.** 단계들이 가로로 놓인 한 줄이다. 끝난 단계는 초록, 지금 단계는 파랑, 다음 단계는 기본색이다. 지금 단계 끝에
   멈춤 표시가 붙는다. 단계를 누르면 그 단계의 업무와 요약이 아래에 열린다.
4. **지금 단계.** 왼쪽은 세부 업무 목록(상태, 담당, 끝난 수/전체 수)이고, 오른쪽은 **작업 카드**다.
   - 작업 카드는 지금 일하는 에이전트마다 한 장이다. 에이전트 이름, "사이클 2 · 검증" 표시, 업무 제목, 경과 시간, 쓴 비용이 들어간다.
   - 카드를 누르면 기존 업무 옆 패널이 열린다.
   - 쉬고 있는 에이전트는 카드로 만들지 않는다. "나머지 8명은 대기 중" 한 줄로 쓴다.
5. 오늘 할 일과 최근 활동은 지금처럼 아래에 둔다.

Business 화면은 지난 사이클과 단계 기록을 계속 가진다.

## 5. 상태와 범위

- **사업 상태:** 사업 없음 → 계획 승인 직후 사이클 짜는 중 → 제안 대기 → 고치는 중 → 단계 실행 중 → 단계 관문 대기 → 사이클 회고 → 다음 제안.
- **단계 안의 상태:** 오너 결정이나 할 일 대기는 주황, 실패는 빨강, 사용량 한도 대기와 워커 꺼짐은 기존 알림으로 보인다.
- **규모:** 단계는 4~9개, 단계당 업무는 2~12개, 동시에 일하는 에이전트는 0~6명이다. 사업이 여럿이면 사업 전환기가 대시보드 범위를 정한다.

## 6. 지킬 것과 하지 않을 것

- 기존 Control Room 세계를 쓴다(DESIGN.md). 상태 색은 상태에만 쓰고, 박스 안에 박스를 넣지 않는다. 숫자 타일 줄은 만들지 않는다.
- 간트 차트, 퍼센트 진행 막대, 추정을 정확해 보이게 꾸미는 숫자를 쓰지 않는다. 진행은 "업무 4/7"처럼 센 수로만 쓴다.
- 예상 시간과 사용량은 "짐작"으로 표시한다(원칙 7).
- 결정 카드, 키크오프 대화, 보드 화면, 업무 옆 패널은 바꾸지 않고 쓴다.
- 모든 문구는 영어와 한국어 카탈로그에 넣는다. "사이클(Cycle)"과 "단계(Stage)"는 `glossary.py`에 새 용어로 올린다.
  코드 이름은 기존 `cycle`을 쓴다.

## 7. 만드는 쪽이 정할 것 (화면이 정하지 않음)

- 단계가 기존 실험, 프로젝트, 업무와 어떻게 이어지는지. 예를 들어 한 단계는 업무 묶음이고, 실험은 홍보와 반응 단계 안에서 돈다.
- "단계 끝에서 멈춤"을 실행 큐에 거는 방식. 시작하지 않은 단계의 일은 큐에 들어가지 않아야 한다.
- 예상 시간과 사용량을 어디서 짐작하는지.
