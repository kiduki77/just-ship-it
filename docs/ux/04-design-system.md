# 04. 디자인 시스템

승인되면 이 문서를 루트 `DESIGN.md`로 옮깁니다. 화면을 만들 때는 이 문서에 없는 값이나 컴포넌트를 새로 만들지 않습니다.
꼭 필요하면 이 문서부터 고친 다음 코드를 씁니다.

## 1. 성격

콘솔은 **조작(Operate) 화면**입니다. 표현보다 다음 세 가지가 우선입니다.
- 훑어 읽기
- 일관성
- 확신도의 가시성

브랜드는 장식이 아니라 정밀한 디테일에서 드러납니다. ID는 고정폭으로, 숫자는 표 숫자로 쓰고, 검증 단계는 모양과 색 두 겹으로 표시합니다.

## 2. 토큰

### 색 역할

색은 **역할 이름**으로만 씁니다. 화면 코드에 hex 값을 쓰지 않습니다.

| 토큰 | 역할 | 라이트 | 다크 |
|---|---|---|---|
| `--bg` | 앱 배경 | #f6f7f9 | #0f1115 |
| `--panel` / `--panel-2` | 표면 / 낮은 표면 | #ffffff / #f1f3f6 | #171a21 / #1e222b |
| `--line` / `--line-strong` | 구분선 / 입력 테두리 | #e2e5ea / #c9ced6 | #2a2f3a / #3a4150 |
| `--text` / `--muted` | 본문 / 보조(모든 표면에서 4.5:1 이상) | #1b1f27 / #5b6475 | #e6e8ee / #9aa2b5 |
| `--accent` | 링크, 선택, 주 버튼. **상태 의미는 없음** | #4f46e5 | #8b87ff |
| `--ok` | 완료, 승인, 지지된 검증 | #067647 | #4ade80 |
| `--run` | 진행 중(정상) | #175cd3 | #7aa7ff |
| `--warn` | 오너 대기, 약한 근거, 보류 | #b54708 | #fbbf24 |
| `--bad` | 차단, 실패, 반박, 반려 | #b42318 | #f87171 |
| `--info` | 종류·분류 표지(상태 아님) | #5b21b6 | #c4b5fd |

색 사용 규칙은 다음과 같습니다.
- 색이 유일한 신호가 되면 안 됩니다. 상태에는 언제나 라벨이나 모양을 함께 둡니다.
- `--bad`는 오너가 지금 행동해야 하는 곳에만 씁니다. 차단 요청, 실패, 반박된 근거가 여기에 해당합니다. 정상 진행에는 빨강도 강조색도 쓰지 않습니다.
- 한 화면에서 강한 색 면(채움)은 하나만 둡니다. 보통 결정 대기 영역입니다.

### 상태 → 톤 매핑(한 곳에서 정의)

| 톤 | 상태 |
|---|---|
| ok | DONE, APPROVED, ANSWERED, ACCEPTED, MERGED, EFFECTIVE, ACTIVE, pass, supported, reproduced |
| run | RUNNING, IMPLEMENTING 등 파이프라인 진행, EVALUATING |
| warn | WAITING_HUMAN, PENDING, DEFERRED, REWORK, weak, unchecked, CLARIFICATION_REQUIRED, conditional |
| bad | FAILED, REJECTED, contradicted, url_unreachable, 차단 |
| muted | CANCELLED, ARCHIVED, SUPERSEDED, EXPIRED, AUTO_APPROVED, 미검토 |

### 확신도 어휘(이 제품만의 시각 언어)

근거는 **종류 = 모양**, **검증 = 색과 단어**의 두 축으로 표시합니다. 두 축을 섞지 않습니다.

| 종류 | 모양 | 뜻 |
|---|---|---|
| 검증된 사실 | ● 채운 원 | 서버 검증과 다른 계열 검토를 모두 통과 |
| 출처 있는 주장 | ○ 실선 원 | 출처는 있지만 독립 검증 전 |
| 계산 결과 | ◇ 실선 마름모 | 재무 엔진이나 분석 샌드박스가 결정적으로 계산 |
| 가정 | ◌ 점선 원 | 모델링을 위한 명시적 가정 |
| 가설 | ◌ 점선 원 + "가설" | 직접 출처 없는 추론 |

이 표에서 정하는 변경은 다음과 같습니다.
- 계산 결과는 출처 있는 주장과 모양이 같았는데, 이제 마름모로 나눕니다.
- 가정과 가설은 모양이 같아 라벨로 구분합니다.

**확신도 막대.** 근거 묶음을 하나의 가로 막대로 보여 줍니다.
- 순서는 `검증 | 출처 | 계산 | 가정 | 가설` 고정입니다.
- 반박된 근거는 막대 뒤에 빨간 숫자로 따로 붙입니다.
- 막대 옆에 항상 숫자 텍스트를 같이 둡니다(스크린리더, 색각이상).

### 타이포그래피

글꼴은 Pretendard → Apple SD Gothic Neo → Malgun Gothic → system-ui이고, 고정폭은 ui-monospace → Cascadia Code → Consolas입니다.

| 단계 | 크기/행간 | 굵기 | 쓰임 |
|---|---|---|---|
| title | 22/1.3 | 700 | 페이지 제목 (페이지당 1개) |
| section | 16/1.4 | 650 | 카드·섹션 제목(h2) |
| sub | 13/1.4 | 600, muted | 섹션 안 소제목(h3) |
| body | 14/1.6 | 400 | 본문, 표 |
| small | 12/1.5 | 400 | 메타 정보, 라벨 |
| micro | 11/1.4 | 600 | 배지, 카운트 (11px 미만은 금지) |
| num | 상속 | tabular-nums | 모든 숫자, ID, 금액 |

- 제목 단계는 건너뛰지 않습니다(h1 → h2 → h3).
- 본문 줄 길이는 최대 72ch로 제한합니다(보고서, 요청 전문, 검토 기록).

### 간격과 형태

- 간격 단위는 4px이고, `4 · 8 · 12 · 16 · 24 · 32 · 48`만 씁니다.
  - 카드 안쪽 여백 16, 카드 사이 16, 섹션 사이 24, 페이지 바깥 여백 24(데스크톱) / 16(모바일).
- 모서리는 컨트롤 8, 카드 10, 배지 999, 종류 표지 4입니다.
- 높이는 컨트롤 32(조밀) / 36(기본)입니다. 터치 대상은 모바일에서 44 이상입니다.
- 그림자는 쓰지 않고, 표면은 선과 배경 차이로 나눕니다. 띄우는 패널(시트, 오버레이)만 그림자 하나를 씁니다.
- 움직임은 150ms ease-out으로 색과 테두리에만 줍니다. `prefers-reduced-motion`이면 스크롤과 펼침 애니메이션을 끕니다.

## 3. 컴포넌트

**기존** 컴포넌트는 그대로 쓰고, **신규** 컴포넌트는 구현 단계에서 만듭니다.

| 컴포넌트 | 상태 | 규칙 |
|---|---|---|
| AppShell / Sidebar | 기존(수정) | 사이드바는 화면 높이 전체를 채웁니다(M10). 그룹은 주 메뉴, 프로젝트, 회사(접힘) 순입니다 |
| PageHeader | 기존(수정) | 제목, 상태 줄, 페이지 동작으로 구성합니다. 긴 설명은 두 줄로 자릅니다 |
| **StatusLine** | 신규 | `● 상태 · 단계 · 멈춘 이유 → [복구 동작]`. 프로젝트 헤더, 홈, 목록에 똑같이 씁니다 |
| **LifecycleStrip** | 신규 | 프로젝트 phase와 J 파이프라인에 공용으로 씁니다. 지난 단계, 현재 단계, 남은 단계를 보여 주고 현재 단계에 `aria-current="step"`을 둡니다 |
| DecisionQueueItem | 기존 | REQ, 한 줄 요청, 차단, 종류, 프로젝트, 요청자, 경과 시간 |
| **DecisionBrief** | 신규 | 무엇을 결정하나, 선택지별 결과, 근거 확신도 |
| **DecisionBar** | 신규(기존 폼 이동) | 항상 화면 안에 있습니다. 주 버튼은 하나이고, 반려는 위험 스타일입니다. 강한 승인은 번호를 입력해야 합니다 |
| Receipt | 기존 | 결정, 선택, 메모, 응답자, 시각, 시작된 일, 다음 결정 |
| Badge | 기존 | 상태 라벨과 톤 매핑을 씁니다. 원래 코드는 툴팁으로 둡니다 |
| KindTag | 기존(수정) | 종류 모양에 마름모를 추가합니다 |
| Verification | 기존 | 검증 라벨과 톤 |
| **EvidenceChip** | 신규 | `[모양 EV-n 검증]`. 누르거나 초점을 받으면 미리보기(주장, 인용, 출처, 검토 메모)가 그 자리에서 열립니다. 본문의 모든 EV 표기를 이것으로 바꿉니다 |
| **ConfidenceBar** | 신규 | 근거 묶음의 종류 분포와 숫자 텍스트 |
| **SinceLastVisit** | 신규 | 범주별 숫자와 상위 3건 링크, [확인함] |
| Card | 기존 | 카드 안에 카드를 넣지 않습니다. 하위 구획은 `entry`(위 구분선)로 나눕니다 |
| Banner | 기존 | 화면 전체에 해당하는 상태(보관, 실패, 끊김)에만 씁니다 |
| Empty / Loading / ErrorState | 기존(수정) | 03의 공통 상태 규칙을 따릅니다. 로딩은 스켈레톤으로 바꿉니다 |
| **StaleNotice** | 신규 | 실시간 갱신이 끊겼을 때 상단의 얇은 띠 |
| Table / FacetChips | 기존 | 필터는 URL에 남깁니다. 숫자 열은 오른쪽 정렬합니다 |
| **DetailPanel** | 신규 | 기본-상세의 오른쪽 패널입니다. 900px 미만에서는 시트가 됩니다 |
| ConfirmInline | 기존 | 되돌릴 수 없는 동작은 두 단계로 확인합니다. 브라우저 대화상자는 쓰지 않습니다 |
| **CommandJump** | 신규 | `Ctrl+K` ID 바로가기 |
| Markdown | 기존 | 같은 출처 링크는 앱 안에서 이동하고, 외부 링크는 "(외부)" 표시를 붙입니다. 스타일 속성은 금지합니다 |

## 4. 화면 규칙(검사 가능한 형태)

1. 한 화면에 주 버튼(채움 강조)은 하나만 둡니다.
2. 오너의 결정이나 동작을 기다리는 것은 그 화면에서 가장 먼저 보입니다(원칙: 결정 먼저).
3. 결정 컨트롤은 1440×900과 390×844에서 스크롤 없이 보여야 합니다.
4. 주장을 인용하는 모든 곳(결정, 요청, 업무 결과, 회의)에서 EV는 EvidenceChip으로 표시합니다.
5. 모든 비동기 동작에는 처리 중, 성공, 실패 세 상태가 있습니다.
6. 모든 데이터 영역에는 로딩, 빈, 오류 상태가 있습니다.
7. 시각은 상대 시각으로 쓰고, 정확한 시각은 툴팁으로 둡니다. 만료처럼 미래 시각은 "n시간 후"로 씁니다.
8. 시스템 코드는 화면에 직접 쓰지 않고 `labels.ts`를 거칩니다. 원래 코드는 툴팁으로 둡니다.
9. 문자열 길이를 가정하지 않습니다. 영어로 바뀌어 40% 길어져도 줄바꿈이나 말줄임으로 버팁니다. 고정 폭 버튼을 쓰지 않습니다.
10. 카드 안에 카드, 옆줄 강조(side-stripe), 그라데이션 글자, 장식 아이콘은 쓰지 않습니다.

## 5. 문구

- **용어는 고정합니다.** 프로젝트(P-n), 업무(T-n), 요청(REQ-n), 근거(EV-n), 결정(DEC-n), 회의(M-n), 명세(spec key), 개발 작업(J-n).
  화면 이름은 결정함, 홈, 업무, 결정, 근거, 문서, 개발입니다.
- **버튼은 동사로 씁니다.** "승인", "반려", "보류", "답변 보내기", "예산 조정 후 재실행". "확인", "OK"처럼 뜻 없는 말은 쓰지 않습니다.
- **오류 문구**는 무엇이 실패했는지, 왜 실패했는지(알면), 무엇을 하면 되는지를 담습니다. 서버 원문은 펼침 안에 둡니다.
- **USD**는 언제나 "환산"과 함께 씁니다. 구독 기반이라 실제 청구가 아니기 때문입니다.
- **에이전트 이름**은 역할로 씁니다(AI CEO, 시장조사, 리스크·감사). 모델과 제공자는 보조 정보입니다.
