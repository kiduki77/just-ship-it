# 07. 로드맵, 시작 인터뷰, 쌓이는 보고서

2026-11-01, 오너 요청 세 가지.

- "로드맵이 없는 게 커. 어느 시점엔 뭘 하고 어느 시점엔 뭘 하는지 모르니까."
- "처음 프로젝트에 대해서 질문하는 것도 있어야 할 거 같아. 최대한 머릿속에서 끄집어내야 해."
- "사업화는 여러 방법으로 진행할 수 있으니 다 포용할 수 있는 UI UX여야 해."

함께 받은 조건. 회의와 업무는 요약 보고서로 쌓여야 하고, 모든 보고는 초등학생도 알아들을 말로 씁니다.

## 지금 왜 "했다, 결정해 줘"로 끝나나

지금 시스템은 사업 하나를 **조사 한 번**으로 다룹니다. 계획, 업무, 회의, 결정을 거쳐 최종 보고서(GO/NO-GO)를 내면 끝납니다.
시작할 때는 이름과 목표 한 줄과 예산만 받습니다(`api/app.py:63`). 그래서 세 가지가 빠집니다.

1. 오너가 아는 사정이 계획에 안 들어갑니다. CEO가 짐작으로 짭니다.
2. "그다음"이 데이터에 없습니다. P-5는 "12주 뒤 다시 판단하자"(REQ-65)를 승인해도 실제로 다시 열리지 않습니다.
3. 한 일이 업무 결과 원문으로만 남습니다. 오너가 읽을 짧은 보고가 없습니다.

## 잘된 스타트업은 어떻게 일하나 (조사 요약)

정해진 순서를 날짜대로 밟은 곳은 찾지 못했습니다. 공통점은 다섯 가지입니다.

| 공통점 | 예 |
|---|---|
| 단계는 날짜가 아니라 **증거**로 넘어갑니다 | Superhuman은 "없어지면 매우 아쉽다" 비율을 22%에서 58%까지 올리며 다음으로 갔습니다 |
| **만들기와 손님 모으기를 같이** 합니다 | Slack은 친한 팀 6~10곳에 먼저 쓰게 하고 몇 번에 걸쳐 넓혔습니다 |
| 일은 **시간과 돈의 한도를 정한 도전**으로 합니다. 다 쓰면 자동으로 늘리지 않고 멈춰서 다시 고릅니다 | Basecamp Shape Up |
| **손님이 생기기 전에는 키우지 않습니다** | YC "원하는 걸 만들기 전에는 팀도 제품도 키우지 마라" |
| **같은 모양의 보고를 같은 주기로** 냅니다. 숫자 몇 개, 도전마다 상태(잘 감·위험·막힘), 잘된 일, 안된 일, 부탁할 것 | YC 투자자 업데이트, Linear 프로젝트 업데이트, Amazon 주간 리뷰 |

시작 인터뷰는 YC 지원서 질문, 린 캔버스, Amazon Working Backwards, Shape Up의 피치, 그리고 The Mom Test("과거에 실제로
한 일을 물어라")를 섞었습니다.

## 새 모습: 말 정리

| 말 | 뜻 |
|---|---|
| **사업** | 오너가 하려는 일 하나. 지금의 P-5가 사업입니다. 사업 안에 여러 도전이 있습니다 |
| **시작 인터뷰** | 사업을 만들 때 CEO가 오너에게 묻는 9묶음 질문. 약 10~12분. 끊고 나중에 이어 할 수 있습니다 |
| **한 장 요약** | 인터뷰로 만든 사업 설명서. 줄마다 출처를 표시합니다(오너가 말함 · 추측 · 모름 · 빈칸). 고칠 때마다 판이 올라갑니다 |
| **사업 방식** | 돈 버는 길. 직접 팔기, 대행, 구독, 물건 팔기, 무료 공개, 광고, 장터, 협력사, 후원·지원금·투자, 직접 쓰기. 2~3가지를 같이 시험할 수 있습니다 |
| **사다리** | "회사가 어디까지 확인했나". 칸 수, 칸 이름, 통과 조건은 사업과 방식에 따라 CEO가 정하고 오너가 고칩니다 |
| **줄** | 동시에 움직이는 일의 갈래. P-5는 제품·손님·돈, 오프라인 서비스라면 영업·현장·허가·돈처럼 사업마다 다릅니다 |
| **도전** | 한 가지 해 볼 일. 누구를 위해, 알고 싶은 것, 시간과 돈의 한도, 성공 신호, 멈출 조건이 붙습니다. 도전 하나가 지금의 "프로젝트 실행" 하나입니다 |
| **판** | 2주 단위. 판이 끝나면 **고르기 회의**에서 다음 판의 도전을 고릅니다 |
| **언덕** | 진행 표시. 왼쪽 오르막은 "알아내는 중", 오른쪽 내리막은 "해내는 중". 퍼센트는 쓰지 않습니다 |
| **오너가 직접** | 회사가 대신 못 하는 일(공개 버튼, 글 올리기, 서류 내기). 준비는 회사가 하고 표시를 따로 합니다 |

**결정 나누기.** 되돌릴 수 있는 결정은 CEO가 하고 기록해서 알려 드립니다. 되돌릴 수 없는 결정(공개, 돈 쓰기, 외부에 보내기,
방향 바꾸기)만 결정함에 올라옵니다. 기준표는 한 장 요약의 "누가 무엇을 정하나" 칸이고, 오너가 고칠 수 있습니다.

## 흐름

1. **사업 만들기.** 이름과 한 줄만 쓰면 바로 시작 인터뷰가 열립니다.
2. **인터뷰.** 한 번에 하나씩 묻습니다. 먼저 자유롭게 답하고, 막히면 예시 보기가 나옵니다. "모르겠어요"는 조사할 일이 됩니다. 묶음이 끝날 때마다 "제가 이해한 건 이거예요, 맞나요?"를 보여 줍니다.
3. **한 장 요약 승인.** 오너가 고치고 승인합니다.
4. **사업 방식 비교.** CEO가 후보 2~5개를 같은 기준(본전이 되려면, 처음 확인할 것)으로 비교하고 추천합니다. 오너가 시험할 조합을 고릅니다.
5. **로드맵 초안.** CEO가 사다리, 줄, 첫 판의 도전을 짭니다. 중요한데 증거가 약한 믿음부터 도전으로 만듭니다.
6. **판 진행.** 도전마다 지금처럼 업무, 회의, 결정이 돕니다. 업무와 회의가 끝날 때마다 세 줄 요약이 보고서에 쌓이고, 매일 아침 브리핑이 나옵니다.
7. **고르기 회의 (2주마다).** 끝난 도전을 정리하고 다음 판을 고릅니다. 고르지 않은 후보는 쌓아 두지 않습니다.
8. **단계 점검.** 사다리 한 칸을 넘을 때, 그리고 정해 둔 점검일(예: 90일 실험 판정)에 3~5분짜리 짧은 인터뷰와 단계 보고를 합니다. 방식이나 사다리를 바꾸는 것도 여기서 합니다.

## 보고서 종류

| 종류 | 언제 | 모양 |
|---|---|---|
| 업무 요약 | 업무가 끝날 때 | 무엇을 했나 · 알게 된 것 · 그래서 다음은 |
| 회의 요약 | 회의가 끝날 때 | 왜 모였나 · 정한 것 · 남은 질문 |
| 하루 브리핑 | 매일 아침 (시각은 오너가 정함) | 어제 한 일 · 숫자 · 막힌 것 · 오늘 할 일 · 오너가 정할 것 |
| 주간 정리 | 매주 | 같은 숫자 몇 개와 6주 추이 · 도전별 상태 · 잘된 일 · 안된 일 · 부탁 |
| 단계 보고 | 사다리 칸을 넘거나 도전이 끝날 때 | 한 것 · 배운 것 · 다음 단계, 반대 의견 함께 |

**쉬운 말 규칙.** 모든 에이전트가 공통으로 받는 글쓰기 규칙(`prompts/company_preamble.md`)에 넣습니다. 어려운 말은 처음 나올
때 풀어 쓰고, 숫자에는 기준(무엇 중 몇)을 붙이고, 추측은 추측이라고 씁니다. 원문은 지금처럼 남기고, 쉬운 요약이 먼저 보입니다.

## P-5를 옮기면

P-5 "Just Ship It 사업화"는 사업이 되고, 지금까지의 실행은 그 사업의 첫 도전 "이 사업이 될까? 조사"(끝남)가 됩니다.
한 장 요약은 지금까지의 지시와 답(REQ-46, 48, 49, 50, 60)으로 미리 채우고, 빈칸만 인터뷰로 묻습니다. REQ-65의 "12주 뒤
판정"은 로드맵의 점검일이 됩니다. 같은 내용으로 두 번 기록된 결정(DEC-5와 DEC-6)은 하나로 보여 줍니다.

## 만드는 순서

순서대로 브랜치를 쌓고, 하나씩 검증한 뒤 오너 동의를 받아 합칩니다. 자세한 실행 계획은 pstack 형식으로 따로 있습니다.

1. **개발팀 pstack 교체.** 개발 컨테이너가 쓰는 gstack 복제판을 정식 pstack으로 바꿉니다. 로드맵과 상관없이 먼저 할 수 있습니다.
2. **사업·도전 데이터.** 사업, 한 장 요약(판 기록), 사업 방식, 사다리, 줄, 도전, 판을 저장하고, 지금 프로젝트를 도전으로 옮깁니다.
3. **쉬운 말과 세 줄 요약.** 공통 글쓰기 규칙, 업무·회의 결과에 세 줄 요약 칸, 보고서 목록.
4. **시작 인터뷰와 한 장 요약.**
5. **사업 방식 비교와 로드맵 초안.**
6. **판, 고르기 회의, 단계 점검, 결정 나누기.**
7. **하루 브리핑과 주간 정리.** 정해진 시각에 도는 예약(지금은 "몇 시간마다"만 됩니다).
8. **로드맵 화면들.**
9. **P-5 옮기기.**

## 하지 않는 것

- 정해진 단계 틀. 칸과 줄은 사업마다 CEO가 정하고 오너가 고칩니다.
- 퍼센트 진행률. 할 일 목록은 하다 보면 늘어나서 퍼센트가 거짓말을 합니다.
- 쌓아 두는 할 일 목록(백로그). 고르지 않은 후보는 버리고, 중요하면 다음 고르기 회의에 다시 나옵니다.
- 외부에 직접 내보내기. 공개, 게시, 연락은 지금처럼 오너가 직접 하거나 보내기 대기함(outbox)에 둡니다.
