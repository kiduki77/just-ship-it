# 시작 대화 화면 설계 요약 (shape)

2026-11-03, `/impeccable shape`. 근거: [08-first-100.md](08-first-100.md) 3절(대화 규칙, 지시서 칸), 10절(스타일),
[04-design-system.md](04-design-system.md)(토큰). 백엔드: `feat/f100-7-kickoff` 64a8a21의 `/api/businesses`, `/api/kickoff/*`.
화면 모드는 Operate입니다.

## 1. 누가, 어떤 상태로 오나

새 사업을 시작하는 오너입니다. 아이디어는 거칠고, 무엇을 물어볼지 모르는 상태로 PC 앞에 10~20분 앉습니다.
중간에 끊고 나중에 돌아오기도 합니다. 이 화면이 끝나면 오너는 "회사가 내 생각을 제대로 알아들었다"고 믿을 수 있어야 합니다.

## 2. 해야 할 일과 성공

- 할 일: CEO의 질문 하나에 답하거나, CEO의 "제가 이해한 건 이거예요. 맞나요?"에 맞다·고친다로 답합니다.
- 성공: 필수 10칸이 "오너가 말함"이나 "확인함"으로 채워지고, 마지막 전체 확인 뒤 지시서를 승인해 첫 일을 시작합니다.
- 이 제품만의 사실: 지시서의 줄마다 출처가 보입니다. CEO가 짐작한 것과 오너가 말한 것이 절대 같아 보이지 않습니다.

## 3. 고른 방향

- **좌우 나란히(오너 선택).** 왼쪽은 대화, 오른쪽은 지시서입니다. 답할 때마다 오른쪽 칸이 채워지고 출처 배지가 붙습니다.
  방금 바뀐 칸은 잠시 강조해서 "내 답이 어디에 들어갔는지"를 보여 줍니다(오너 원칙 4: 오너의 말이 계획을 바꾸는 게 보인다).
- **질문은 한 번에 하나.** 대화 칸의 맨 아래 CEO 말이 지금 할 일입니다. 입력칸은 그 바로 아래에 있습니다.
- **스타일(오너 지정).** 흰 바탕, 그림자 없음, 검정·회색 두 단계 글자, 굵은 핵심어 + 회색 보조 정보, 색은 배지와 상태에만,
  보조 동작은 테두리 버튼.

## 4. 범위

- 데스크톱 전용입니다(오너 결정). 1280px 이상에서 좌우 나란히, 그보다 좁으면 지시서를 접어 위쪽 요약 막대로 바꿉니다.
  휴대폰 전용 화면은 만들지 않지만, 좁은 화면에서 깨지지는 않게 합니다.
- 들어가는 것: 새 사업 만들기(이름, 한 줄, 붙여 넣을 자료), 대화, 지시서 보기, 마지막 확인, 승인과 시작.
- 들어가지 않는 것: 지시서 직접 편집(백엔드 미지원, 고칠 곳은 대화로 말함), Slack 대화, 점검일 재정렬 대화.

## 5. 상태와 범위

| 상태 | 화면 |
|---|---|
| 새 사업 | 이름, 한 줄, "가진 자료가 있으면 붙여 넣으세요"(선택) 세 칸. 시작 버튼 하나 |
| CEO가 생각 중 | 턴 하나에 30~90초. 대화 끝에 "CEO가 다음 질문을 정리하고 있어요"와 조용한 진행 표시. 입력칸은 잠금 |
| 오너 차례 | 질문 + 입력칸. 아래에 조용한 글자 버튼 "모르겠어요", "나중에 할게요" |
| 확인·제안 턴 | CEO 말 아래 [맞아요] [고칠게요]. "고칠게요"는 입력칸에 초점 |
| 망설임 | 짧은 답, "모르겠어요", 또는 20초 넘게 입력이 없으면 예시 답(칩)이 나타남(오너 선택). 예시에는 항상 "다른 거예요" |
| 사용량 대기 | "사용량 상한에 닿아 내일 00:00에 이어 갑니다" 같은 이유와 재개 시각. 대화는 그대로 보임 |
| 멈춤(나중에·실패) | 멈춘 이유 한 줄과 [이어 하기] |
| 마지막 확인 | 지시서 전체 요약 + "제일 틀렸을 것 같은 곳이 어디예요?" |
| 끝남 | 지시서 머리줄이 "승인 대기"로 바뀌고 [지시서 승인하고 시작하기] 하나가 주 버튼 |

분량: 질문 최대 20턴. 오너 답은 한 줄부터 몇 문단까지, 붙여 넣는 자료는 수천 자까지. 지시서는 15칸, 칸마다 0~5줄.
질문 수는 "7/20"처럼 작게 보조로만 보이고, 주된 진행 표시는 "필수 10칸 중 6칸"입니다.

## 6. 상호작용과 배치

- 지시서 패널: 머리줄 "**업무 지시서** · 초안 · 필수 10칸 중 6칸". 필수 칸이 먼저, 나머지 5칸은 아래 "더 있는 칸"에.
  칸마다 이름, 출처 배지, 내용 두 줄(넘치면 펼치기). 빈 필수 칸은 "아직"으로 비워 둡니다.
- 출처 배지 네 가지(오너가 말함, 확인함, 짐작, 모름)는 색과 모양을 함께 다르게 합니다(색만으로 구분하지 않음).
  배지 어휘는 04의 확신도 어휘와 겹치지 않게 따로 둡니다.
- 대화의 줄 출처: 지시서의 줄을 누르면 그 줄이 나온 대화 턴으로 이동합니다(`source: kickoff:<session>:<n>`).
- 키보드: Enter 보내기, Shift+Enter 줄바꿈. 확인 턴에서 Y/N 단축키는 두지 않습니다(실수 방지).
- 실시간: 턴이 끝나면 SSE로 갱신합니다. 오너가 다른 화면에 가 있으면 대시보드의 "결정 필요"에 "CEO가 질문했어요"가 뜹니다.

## 7. 제약과 열린 결정

- 한국어 먼저, 영어가 들어와도 깨지지 않게 칸 이름과 버튼 길이를 가정하지 않습니다. WCAG 2.2 AA, 키보드로 끝까지 갈 수 있음.
- 기존 컴포넌트(배지, 버튼, 머리줄)를 다시 쓰고, 새로 만드는 것은 대화 말풍선과 지시서 칸 행입니다.
- 만드는 사람이 정하지 말 것: 출처 배지의 이름(위 네 가지 고정), 질문 상한(20), 승인 전 시작 불가.
- 진입점: 대시보드의 "새 사업 시작" 버튼과 사업 목록에서 진행 중인 대화 이어 하기.
