# 05. 구현과 검증

## 1. 시나리오 측정

측정은 헤드리스 브라우저(pstack browse)에서 1440×900과 390×844로 합니다. 대상은 실데이터 P-5와 [TEST] 하네스 프로젝트입니다.
재설계 전 값을 지금 기준선으로 잡고, 구현 뒤 같은 스크립트로 다시 잽니다.

| 시나리오 | 지표 | 기준선 (2026-11-01, main) | 목표 |
|---|---|---|---|
| S1 차단 요청 해제 | 홈에서 결정 화면까지 클릭 수 | 1 | 1 |
| | 결정 버튼까지 스크롤(1440×900) | REQ-66 버튼이 상세 패널 안 y=2,700px에 있어 약 1,800px 스크롤. REQ-67 약 450px. REQ-64·65는 스크롤 없음 | 모든 요청에서 0 |
| | 결정 전에 결과를 볼 수 있나 | 아니요(결정 뒤 영수증에만 나옴) | 예 |
| S4 현황 파악 | 멈춘 이유를 찾는 데 드는 화면 수 | 2(대시보드 → 프로젝트 배너) | 0(홈의 상태 줄) |
| | 지난 방문 이후 변화 | 없음 | 홈에 있음 |
| | 프로젝트 개요 높이 | 8,393px | 2,000px 이하 |
| S5 결론 신뢰 판단 | 결정 하나의 근거 확신도를 알기까지 이동 | 근거 원장으로 이동해 EV를 하나씩 검색 | 0(같은 자리에서 확신도 막대와 칩) |
| S8 복구 | 콘솔로 끝낼 수 있나 | 아니요(CLI) | 예 |
| 전체 | 진입점 수 | 16 (중복 3) | 13 (중복 0) |

**정성 검증.** 오너가 실제로 한 주 동안 쓰면서 다음 세 가지를 기록합니다.
- 결정 하나에 걸린 시간
- 결정한 뒤 뒤집은 횟수(오판)
- "어디 있지?"라고 찾은 횟수

설계 문서는 이 수치를 대신하지 못합니다.

## 3. 구현 순서

화면마다 하나씩 브랜치를 만들고, 각 단계가 끝나면 오너 확인을 받고 `main`에 합칩니다.

1. **기반.** 토큰 정리, 상태→톤 매핑을 한 곳에 모으기, AppShell(사이드바 높이), DetailPanel, StatusLine, LifecycleStrip, EvidenceChip, ConfidenceBar.
   새 주소 체계와 기존 URL 리다이렉트.
2. **결정함(SC-02).** DecisionBrief, DecisionBar, 처리됨 목록 정리. S1–S3가 핵심이라 가장 먼저 합니다.
3. **프로젝트 개요(SC-04)와 결정(SC-06).** 개요를 줄이고, CEO 검토 기록과 회의를 결정 탭으로 옮깁니다.
4. **홈(SC-01).** 지난 방문 이후, 프로젝트 상태 줄.
5. **업무(SC-05), 근거(SC-07), 문서(SC-08), 개발(SC-09).**
6. **복구 동작(S8)과 지시 남기기(S6).** 백엔드 추가가 필요합니다.
7. **회사 관리(SC-10–13), ID 바로가기(SC-14).**
